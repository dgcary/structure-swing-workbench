# M4.5｜筹码成本分布估算 v1

本模块输出**概率估算**，不是券商或交易所披露的真实持仓。不能从成交数据识别哪位投资者、哪一批历史成本筹码实际卖出，也不生成支撑/压力、趋势或买卖结论。

## 输入口径

使用 `app.chip_cost.estimate_distribution`，输入严格按日期递增的 `DayObservation`。每条记录包括：

- `bar`：M4 标准 `Bar`（带时区的 OHLCV），`volume` 必填。
- `turnover_rate`：**0～1 的比例**（5% 填 `Decimal("0.05")`，不是 5）。
- `floating_shares`：当日流通**股数**，不是“手”或“万股”；与分钟/日线成交量的计量单位应明确转换一致。
- `source`、`quality`：来源和 M4 数据质量；历史任一天缺失必要字段或标记 ERROR/MISSING 时不返回伪造分布。
- `minute_bars`：可选。仅在分钟成交量完整、时间递增、日期一致，且分钟量合计与日量偏差不超过 1% 时使用分钟成交权重；否则回退日线价格区间均匀分配并标记。
- `price_basis="raw"`：**只接受未复权价格**；前复权/后复权输入直接拒绝，防止历史价格与当前价格混算。
- `split_factor`：送转/拆股后流通股数相对旧股数的倍率（如 10 送 10 为 2），在当日换手前将历史价格除以倍率、股数乘以倍率。
- `corporate_action_checked`：若未核实是否有公司行为，结果标记 `CORPORATE_ACTION_UNVERIFIED`，并将汇总数据质量降为 `UNVERIFIED`（若原状态更差则保留），不能把无信息当作无事件。

第一版数据源的日线 `Bar` 不直接携带换手率、流通股本、送转信息；**调用方必须从可核验来源补齐**，不得用成交量臆造流通股本，也不得假设分钟/日线成交量的单位相同。


- 若行情报告换手率为 **0** 但成交量大于 **0**，可能是百分比四舍五入或单位不一致；保留估算，但将 `source_quality` 降至 `UNVERIFIED`，并添加 `ZERO_TURNOVER_WITH_POSITIVE_VOLUME`，不能静默标记为已核实。相反，**正换手率与零成交量**视为数据冲突，不返回估算。

## 算法与可解释性

1. 第一日将未换手部分暂按当日收盘价初始化，将当日换手部分按当日成交价桶分配；标记 `INITIAL_COST_BOOTSTRAP`，不宣称识别首日以前的真实成本。
2. 后续每日将旧筹码按 `(1 - turnover_rate)` 等比例衰减，再按分钟成交量权重或日线 OHLC 区间均匀近似加入当日 `floating_shares * turnover_rate`。**衰减是概率假设**，不是识别了哪批筹码被卖出。
3. 流通股本变化先于换手处理：增加部分暂放当日收盘价桶，减少部分按比例缩减历史估计，均有明确警告。送转使用 `split_factor` 先变换旧分布。
4. 使用 `Decimal` 计算价格桶与数量，默认桶宽 0.10 元；结果保留每桶估算股数、占比、总量、与流通股数偏差、模型版本、计算时间、来源与质量。
5. 平均成本为价格桶加权均值；获利盘/套牢盘/平价盘分别指**估算成本**低于/高于/等于最新收盘价的股数比例。70%/90% 成本区间为加权分位数 15～85% / 5～95%；10% 集中度定义为收盘价上下各 5% 内的估算筹码比例。这些定义不是技术支撑/压力判定。

## 边界与未实现范围

- 历史空输入返回 MISSING；缺换手率、流通股数或成交量时不输出成本统计。
- 未核实公司行为、分钟数据不完整、流通股本变化和首日成本初始化都会在 `warnings` 留痕。
- 不支持复权价与原始价混用，不推断未知送转倍率；如缺公司行为信息，输出显式不确定性。
- 不接入券商真实持仓、不绘制 Web 筹码图、不做二维成本×持有时间模型，不修改 M2 审计规则，也不提前开发 M5。
- 固定样例测试可在 `backend` 执行 `pytest tests/test_chip_cost.py`；无需访问外部行情服务。
