# M8 手工账户台账

用户交易频率低，选择在家中同一 Wi-Fi 下让手机和电脑读取同一份手工记录。工作台新增独立的「手工台账」页：首次登记账户观察时间、资金与各批持仓；以后操作时复制上一版、填写买卖记录并手动确认新的持仓状态。每次提交都是新的完整版本，旧版保留。买入时间或投入金额未知时可留空；不得补造。

这是一份**用户自报台账**。页面显示买入时间、持有数量和登记投入金额；投入金额不是实时市值。操作记录只用于回看，不自动推算券商持仓、可用资金、成本价、T+1 可卖数量或当日完整 T 次数。数据库表与正式 `execution_fills`、`account_snapshots` 分开，正式总览及交易审计不采信这些记录；`broker_reconciled=false`、`full_account_verified=false`、`trade_execution_enabled=false`。

## 启用条件

- 默认为关闭。设置 `WORKBENCH_MANUAL_JOURNAL_ENABLED=true` 与独立随机生成的 32 字符以上 `WORKBENCH_MANUAL_JOURNAL_TOKEN`，并完成 Alembic 迁移。
- API 的读与写均需 Bearer 访问口令。网页只在内存中保留口令，切换离开页面后清除；局域网明文 HTTP 页面不会发送口令。服务端也拒绝远程明文 HTTP 与伪造的 `X-Forwarded-Proto` 请求。
- **手机实用部署尚未完成。** 现有 Docker Compose 暴露开发端口，其他工作台只读接口也没有统一登录保护。必须先设置覆盖整个工作台的单用户访问保护、可信 HTTPS 反向代理、仅内网访问及数据库不外露，再在手机 Safari 实机验证。不要直接把当前 5173/8000 开发端口作为家庭共享入口。
- 本地回环 HTTP 仅供开发验证。任何代理都须正确地把受信任 TLS 连接呈现为 ASGI `https`；不能让任意请求头伪造该事实。

## 数据规则

- 表单中的观察时间是用户查看账户的时间，服务端另记提交时间；未来时间、无时区时间、非法/过精度数值会被拒绝。
- 最新版本号由服务器检查。手机与电脑基于同一版同时修改时，一方成功，另一方收到冲突而不覆盖既有记录。失败时表单保留。
- 服务器只返回最近 20 个版本并说明总版本数；较早版本仍保存在数据库，后续可增加分页入口。
- 未录入不等于空仓。用户保存空持仓表也仅是该次自报空仓，不是券商账户证明。
