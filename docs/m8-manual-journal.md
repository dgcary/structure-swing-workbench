# M8 手工账户台账

用户交易频率低，选择在家中同一 Wi-Fi 下让手机和电脑读取同一份手工记录。工作台新增独立的「手工台账」页：首次登记账户观察时间、资金与各批持仓；以后填写买卖记录，由服务端从最新版本自动增减对应持仓数量。人工校正仍可复制上一版并保存新的完整版本。每次提交都是新的版本，旧版保留。买入时间或投入金额未知时可留空；不得补造。

这是一份**用户自报台账**。页面显示买入时间、持有数量和登记投入金额；投入金额不是实时市值。操作记录只用于回看，不自动推算券商持仓、可用资金、成本价、T+1 可卖数量或当日完整 T 次数。数据库表与正式 `execution_fills`、`account_snapshots` 分开，正式总览及交易审计不采信这些记录；`broker_reconciled=false`、`full_account_verified=false`、`trade_execution_enabled=false`。

## 启用条件

- 默认为关闭。设置 `WORKBENCH_MANUAL_JOURNAL_ENABLED=true` 与独立随机生成的 32 字符以上 `WORKBENCH_MANUAL_JOURNAL_TOKEN`，并完成 Alembic 迁移。
- API 的读与写均需独立的 `X-Workbench-Journal-Token` 访问口令，避免与整站登录共用 `Authorization`。网页只在内存中保留口令，切换离开页面后清除；局域网明文 HTTP 页面不会发送口令。服务端也拒绝远程明文 HTTP 与伪造的 `X-Forwarded-Proto` 请求。
- 已准备独立的[家庭运行配置](m8-home-deployment.md)：全站登录、内部 CA HTTPS、仅固定内网 IP 的 443 端口对外，数据库与后端不发布端口。**尚未在用户的 Ubuntu/NAS 与手机 Safari 实机验证**；现有 5173/8000 开发端口不可作为家庭共享入口。
- 本地回环 HTTP 仅供开发验证。任何代理都须正确地把受信任 TLS 连接呈现为 ASGI `https`；不能让任意请求头伪造该事实。

## 数据规则

- 表单中的观察时间是用户查看账户的时间，服务端另记提交时间；未来时间、无时区时间、非法/过精度数值会被拒绝。
- 最新版本号由服务器检查。手机与电脑基于同一版同时修改时，一方成功，另一方收到冲突而不覆盖既有记录。失败时表单保留。
- 服务器只返回最近 20 个版本并说明总版本数；较早版本仍保存在数据库，后续可增加分页入口。
- 未录入不等于空仓。用户保存空持仓表也仅是该次自报空仓，不是券商账户证明。
- 卖出须填写各买入批次的扣减数量，合计与成交数量相等；一笔卖出可一次扣减多批。仅有一批时页面可自动分配全部卖出量。部分卖出后剩余投入金额标未知，等待用户核对，不自动采用 FIFO、均价或券商成本算法。操作后资金未填写时也标未知，不从买卖价推断可用资金。
- 晚间补录多笔成交时，按真实成交先后登记。每条操作的观察时间可以是同一次当前账户查看时间；补录全部完成前，中间版本只是尚未录齐的手工状态。人工校正会重新设定时间起点，不能再插入校正之前的操作。
- 初次对齐及人工校正接口不接受买卖操作；买卖只能通过自动更新持仓接口登记，避免记录和数量相互矛盾。
