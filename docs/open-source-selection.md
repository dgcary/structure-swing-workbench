# 开源组件初选

## 原则

系统采用“模块化拼装”，不选一个庞大交易平台强行承载所有业务。

选择标准：

- 活跃维护；
- 许可证清晰；
- Docker / Linux 友好；
- Python 生态兼容；
- A 股支持；
- 易于二次开发；
- 模块可替换。

## 第一批候选

### FastAPI

用途：后端 API。

原因：
- Python 原生；
- Pydantic 数据模型适合计划 / 动作 / 审计结果；
- 自动 OpenAPI；
- 便于和现有 Python 研究系统集成。

许可证：MIT。

### PostgreSQL

用途：计划、版本、动作、成交、持仓、审计与复盘数据。

原因：
- 数据一致性要求高；
- 关系模型适合交易审计链；
- JSONB 可存扩展研究信息。

### AKShare

用途：第一版 A 股客观行情和基础证券数据适配器。

注意：
- 外部上游接口可能发生变化；
- 只能存在于适配层；
- 核心业务不得直接依赖 AKShare 函数。

许可证：MIT。

### KLineChart

用途：Web 端 K 线、指标和画线。

原因：
- 专注金融 K 线；
- 支持移动端；
- 体积轻；
- 可扩展；
- TypeScript 类型完整。

许可证：Apache-2.0。

### TradingAgents / StockResearchPack

用途：研究模块。

策略：
- 保持现有项目独立；
- 通过标准研究适配器接入；
- 不复制研究代码到本仓库；
- 研究结论不能直接越过审计引擎生成交易指令。

### vn.py

定位：暂不作为本系统主框架。

未来用途：
- 如果需要接券商 / 交易网关，可以评估作为交易接口适配层。

原因：
- 本系统是“人工决策 + 纪律审计”，不是自动量化交易框架；
- 直接采用完整 vn.py 作为主框架会增加不必要耦合。
