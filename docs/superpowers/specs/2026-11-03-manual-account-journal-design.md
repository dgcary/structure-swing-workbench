# 手工账户台账设计

## 意图

用户交易频率低，希望在家中同一 Wi-Fi 下用手机和电脑查看同一份手工记录。首次录入账户资金与各笔持仓，之后操作时记录买卖时间、数量、价格和费用，并确认操作后的持仓。这样可追溯买入时间与投入金额，无需券商非公开接口。

## 方案

- 浏览器本地保存加导出：开发简单，但两台设备无法自动同步；不符合用户选择。
- 将手工记录直接写入现有正式成交/账户表：复用投影方便，但会把自报材料混入正式审计与券商数据，风险过高。
- **选用独立的服务端手工台账**：新增只追加的完整快照修订，记录每笔持仓的买入时间、数量、投入金额，可附带一次操作详情。手机与电脑读取同一 PostgreSQL 记录；不进入正式成交、券商持仓或交易许可链路。一次交易后复制上次快照供用户修改，避免重新填写全部持仓。

## 行为与边界

- 一条修订包含用户填写的观察时间、可选可用资金、可选权益、持仓买入批次、可选买卖操作及备注。每笔持仓可填写投入金额，不推断当前市值；同证券可有多个买入批次。已有持仓的买入时刻或投入金额若不记得，可以留空并显示未知，不捏造。空持仓表是用户明确记录的“自报空仓”，不是券商证明。
- 保存为只追加修订；修改产生新版，保留历史。提交时带当前版本号；跨设备同时编辑导致版本冲突时拒绝覆盖，并要求刷新。服务端生成记录时间。
- 页面始终标明“手工记录／未与券商核对”，显示用户观察时间和服务端记录时间。与现有正式总览分区展示，不将其提升为实时账户、可信 T+1 可卖量、完整 T 次数、CORE/T 当前风险或交易权限。
- 默认关闭。读取和写入都要求强随机访问令牌。远程设备只可经可信 HTTPS 使用；本机回环 HTTP 可用于开发。令牌只保存在页面内存，不写入浏览器存储或日志。
- 家中同一 Wi-Fi 的手机访问需要后续配置可信 HTTPS 与单用户访问入口；当前 Docker 开发端口不能直接作为已验收的手机入口。数据库不得对局域网公开。

## 验收

- 有效初始记录、追加操作与新版快照可在两个独立客户端读取；冲突写入、无令牌、弱令牌、远程 HTTP、非法时间/数值/重复提交均失败且不泄露数据。
- 前端可录入、回看最新和历史记录，刷新后保留，明确标注自报来源；令牌不进本地存储，失败不丢表单。
- 不改既定交易规则，不调用券商接口，不自动下单。M8 Gate 仍取决于正式数据与手机 HTTPS 实机验收。
