# 手工账户台账设计

## 意图

用户交易频率低，希望在家中同一 Wi-Fi 下用手机和电脑查看同一份手工记录。首次录入账户资金与各笔持仓，之后操作时记录买卖时间、数量、价格和费用，由工作台从已登记持仓自动增减数量。这样可追溯买入时间与投入金额，无需券商非公开接口。

## 方案

- 浏览器本地保存加导出：开发简单，但两台设备无法自动同步；不符合用户选择。
- 将手工记录直接写入现有正式成交/账户表：复用投影方便，但会把自报材料混入正式审计与券商数据，风险过高。
- **选用独立的服务端手工台账**：新增只追加的完整快照修订，记录每笔持仓的买入时间、数量、投入金额。手机与电脑读取同一 PostgreSQL 记录；不进入正式成交、券商持仓或交易许可链路。初始快照或人工校正可复制上一版编辑；日后买卖由服务端在最新版本上原子地生成下一版。

## 行为与边界

- 一条修订包含用户填写的观察时间、可选可用资金、可选权益、持仓买入批次、可选买卖操作及备注。每笔持仓可填写投入金额，不推断当前市值；同证券可有多个买入批次。已有持仓的买入时刻或投入金额若不记得，可以留空并显示未知，不捏造。空持仓表是用户明确记录的“自报空仓”，不是券商证明。
- 保存为只追加修订；修改产生新版，保留历史。提交时带当前版本号；跨设备同时编辑导致版本冲突时拒绝覆盖，并要求刷新。服务端生成记录时间。
- 录入买入时自动增加一批持仓，并保留买入时刻。只有费用已填写且数量×价格＋费用能在四位小数内精确表示时才填写该批投入金额，否则为未知。录入卖出时用户填写各买入批次的扣减数量，合计必须等于成交数量；一笔卖出可原子地扣减多批。部分卖出后剩余数量自动更新，剩余投入金额转为未知，等待用户手工核对，不擅自选择成本分摊规则；全部卖出则移除该批。
- 事后补录多笔操作时按成交先后登记，已有操作的观察时间不妨碍晚间继续补录下一笔；人工校正则重新设定时间起点。补录完毕前的中间版本是尚未录齐的手工状态。
- 每笔操作可同时填写操作后资金和权益；未填写时新版本对应值为未知，不延用操作前的旧资金。初始快照必须先建立，之后才能使用自动增减操作。
- 页面始终标明“手工记录／未与券商核对”，显示用户观察时间和服务端记录时间。与现有正式总览分区展示，不将其提升为实时账户、可信 T+1 可卖量、完整 T 次数、CORE/T 当前风险或交易权限。
- 默认关闭。读取和写入都要求强随机访问令牌，通过与整站登录分离的 `X-Workbench-Journal-Token` 发送。远程设备只可经可信 HTTPS 使用；本机回环 HTTP 可用于开发。令牌只保存在页面内存，不写入浏览器存储或日志。
- 家中同一 Wi-Fi 的手机访问使用独立家庭 Compose 配置：全站登录、内部 CA HTTPS、固定内网 IP 的 443 端口，后端与数据库不对局域网公开。仍需在用户设备上部署、安装根证书及手机 Safari 实机验收；当前 Docker 开发端口不能直接作为家庭入口。

## 验收

- 有效初始记录、追加操作与新版快照可在两个独立客户端读取；冲突写入、无令牌、弱令牌、远程 HTTP、非法时间/数值/重复提交均失败且不泄露数据。
- 前端可录入、回看最新和历史记录，刷新后保留，明确标注自报来源；令牌不进本地存储，失败不丢表单。
- 不改既定交易规则，不调用券商接口，不自动下单。M8 Gate 仍取决于正式数据与手机 HTTPS 实机验收。
